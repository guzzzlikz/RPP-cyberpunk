# Паспорт жителя — `rpp_identity`

Мод даёт каждому игроку RP-личность: имя, фамилию и уникальный номер жителя.
Код: `server/resources/rpp_identity/`.

## Как это выглядит для игрока

1. **Первый вход.** Когда персонаж загрузился в мир, открывается редактор внешности
   (рипердок). Игрок настраивает персонажа и сохраняет.
2. **Имя.** Появляется форма «Паспорт»: имя и фамилия. Разрешены русские и латинские
   буквы, дефис и апостроф внутри слова, от 2 до 20 символов. Первая буква
   становится заглавной автоматически.
3. **Подтверждение.** Окно «Паспорт оформлен» показывает номер, например
   **Житель #1001**, и имя. Номер выдаётся по порядку и никогда не повторяется.
4. **Над головами** других игроков видно:
   - `Житель #1042` — незнакомец с паспортом;
   - `Имя Фамилия · #1042` (зелёным) — знакомый: имя и номер жителя, номер виден всегда;
   - `Незнакомец` — игрок без паспорта.

   Скрыть или показать ники над головами — **F1** (переназначается в настройках клавиш
   Open77, выбор запоминается). Пузыри сообщений чата при этом остаются.
5. **Знакомство.** Зажать **ALT**, кликнуть по игроку (до 5 м) → **«Познакомиться»**.
   Второй игрок получает уведомление и соглашается тем же пунктом меню на вас или
   командой `/accept` в течение 60 секунд. После этого **оба** видят имена друг друга.
   Знакомства сохраняются между заходами.

Если закрыть форму кнопкой «Позже», её можно открыть снова командой `/register`.

## Команды

| Команда | Доступ | Что делает |
|---|---|---|
| `/passport` | Игрок | Свой номер, имя и число знакомых |
| `/register` | Игрок | Открыть оформление паспорта, если его нет |
| `/accept` | Игрок | Принять последнее предложение знакомства |
| `/decline` | Игрок | Отклонить предложения знакомства |
| `rpp.identity.info <playerId>` | Админ | Аккаунт ↔ номер жителя ↔ имя |
| `rpp.identity.reset <playerId>` | Админ | Сбросить паспорт, игрок проходит регистрацию заново |

Админские команды требуют права `command.rpp.identity.info` и `command.rpp.identity.reset`
(Warden → Players → Rights или `acl.jsonc`). `playerId` — это ID сессии, его показывает `/id`
или `admin.read.players`.

## Создание внешности

С Open77 77.248 внешность создаётся в штатном ресурсе **`open77_creator`** прямо в мире,
а не в меню игры. Режим включает freeroam (`setCreationMode("runtime")`).

- Редактор сам открывается новому персонажу, когда тот встал в мире.
  `rpp_identity` ждёт, пока его закроют, и только потом показывает форму имени.
- Если за `creatorWaitSeconds` (25 с) редактор не открылся сам (например, у персонажа уже
  есть сохранённый образ), `rpp_identity` открывает его явно.
- MySQL для этого шага не нужна. Без базы образ живёт до перезапуска сервера,
  с базой хранится в таблице `open77_creator_looks`.
- Изменить внешность позже: команда `/creator`.
- Игроки, создавшие персонажа до 77.248, при первом входе тоже увидят редактор
  один раз: у них ещё нет записи в `open77_creator_looks`.

Если `open77_creator` не запущен, работает старый путь: редактор рипердока
`open77_appearance` (режим `appearanceMode`), и только при включённой MySQL.

## Настройки

Файл `shared/config.lua`:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `firstCitizenId` | `1001` | Первый номер жителя |
| `citizenPrefix` | `"Житель"` | Текст перед номером |
| `unregisteredLabel` | `"Незнакомец"` | Подпись над игроком без паспорта |
| `nameMinLength` / `nameMaxLength` | `2` / `20` | Длина имени и фамилии |
| `customizeBeforeName` | `true` | Открывать редактор внешности перед именем |
| `appearanceMode` | `"ripperdoc"` | `ripperdoc` (всё тело) или `hairdresser` (причёска) |
| `introduceDistance` | `5.0` | Дистанция знакомства, м |
| `offerSeconds` | `60` | Сколько живёт предложение знакомства |
| `nameplateDistance` | `40` | Дальность подписи над головой, м (не меньше дальности крика — для пузырей чата) |
| `knownColor` | `"#5CF2A6"` | Цвет подписи знакомых |

После изменения настроек перезапустите сервер или выполните в консоли `restart rpp_identity`
(игрокам потребуется переподключиться: ресурс использует WebUI).

## Хранение данных

Ключ игрока — `GetPlayerIdentifier()`, GUID аккаунта Open77 (не ник). Это тот же
`user_id`, что у персонажа в `open77_characters`.

**С базой (обычный режим)** — MySQL, база `open77`. Таблицы создаются сами при старте:

| Таблица | Колонки |
|---|---|
| `rpp_citizens` | `citizen_id` (номер жителя, с 1001), `user_id`, `first_name`, `last_name`, `created_at`, `updated_at` |
| `rpp_acquaintances` | `user_id`, `known_user_id` (кого знает), `created_at` — по строке на каждое направление |

Посмотреть всех жителей:

```
db\server\bin\mariadb.exe -h 127.0.0.1 -u root -p open77 -e "SELECT * FROM rpp_citizens"
```

Имя с персонажем внешности: `JOIN open77_characters USING (user_id)`.

**Без базы** — `Open77.kvp` (файл `kvp.json` ресурса на сервере):

| Ключ | Значение |
|---|---|
| `rpp.citizen.seq` | Следующий свободный номер |
| `rpp.citizen.<guid>` | `{"id":1001,"first":"Имя","last":"Фамилия"}` |
| `rpp.known.<guid>` | Список GUID знакомых |

Когда база появляется, записи из kvp при старте ресурса переносятся в MySQL
(в логе: `moved N passport(s) from kvp to MySQL`). В консоли сервера при старте видно,
какое хранилище выбрано: `passports are stored in MySQL ...` или `... in kvp`.

## Для других модов

Серверные экспорты:

```lua
local citizen = exports.rpp_identity:getCitizen(playerId)   -- {id, first, last} или nil
local known = exports.rpp_identity:areAcquainted(a, b)      -- true/false
```

Серверные события:

```lua
AddEventHandler("rpp_identity:registered", function(playerId, citizen) end)
AddEventHandler("rpp_identity:introduced", function(playerA, playerB) end)
```

## Ограничения

- Чат по-прежнему показывает **имя аккаунта** Open77 (это делает `open77_chat`).
  Для полного RP-режима чат нужно доработать отдельно.
- В соревновательных режимах (PvP, Deathmatch) мод `open77_nameplates` сам управляет
  подписями (свои/чужие). Обе системы выставляют подписи, и какая окажется поверх,
  зависит от Open77. Во Freeroam конфликта нет.
- Игрок, только что зашедший на сервер, первые секунды может видеть над другими
  стандартные подписи (имена аккаунтов), пока не придёт список от сервера.
- Регистрация стартует после полной загрузки персонажа (`gameplayReady`). Если загрузка
  у игрока сорвалась (ошибка `OP77-INIT-001`), форма сама не откроется — поможет `/register`.
