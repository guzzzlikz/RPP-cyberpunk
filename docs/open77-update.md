# Обновление Open77 (сейчас 77.248)

Сервер работает на версии **2.50.0+op77.248** (`server/package-manifest.json`).
Игрокам нужен клиент **той же версии**: со старым клиентом на сервер не зайти.

## Что пришло в 77.248

| Что | Где | Как у нас |
|---|---|---|
| Создание персонажа прямо в мире, а не в меню игры | `system/open77_creator` | Включено. Заменило наш шаг внешности в `rpp_identity`: сначала создание персонажа, потом паспорт ([rpp_identity.md](rpp_identity.md#создание-внешности)). Переведено, перекрашено. `/creator` открывает снова |
| Слои одежды в гардеробе | `open77_wardrobe_ui`, вкладка «Слои» | Переведено |
| Сканер и квикхаки | `system/open77_quickhack` | Лежит на сервере, но **выключен**, как в штатной поставке. Это фреймворк: своих скриптов в нём нет, только примеры «Пинг», а пример для игроков показывает ник аккаунта и ломает анонимность паспортов. Чтобы включить, нужен свой ресурс с `dependency "open77_quickhack"` и своими скриптами. Интерфейс уже переведён и перекрашен |
| Телевизор с YouTube | `system/open77_tv` вместо `open77_media` | `/tv [url]` только для админов. Автоспавн телевизора перед каждым игроком при старте убран. Вкладка «Телевизоры» в меню freeroam удалена, как и в 77.248 |
| Полоска noclip у админа | `open77_admin` | Переведено |
| Экран ошибки скрипта сервера при подключении | `open77_shell` | Переведено, перекрашено |

Как и раньше, `open77_scenes` и `open77_braindance` лежат на сервере, но не запускаются:
они включаются только командой `ensure` или зависимостью другого ресурса.

## Как обновлять в следующий раз

Наши правки лежат прямо в штатных ресурсах (`system/open77_chat`, `open77_pause`, перевод,
тема). Поэтому новую версию **нельзя просто скопировать поверх**: потеряются правки.
Делаем трёхстороннее слияние в git.

- **База** — чистая версия, от которой мы ушли.
- **Наше** — текущая ветка.
- **Их** — новая версия.

1. Распаковать новый архив в отдельную папку, например `K:\RPPCyber\<версия>\`.
   Добавить её в `.git/info/exclude`, чтобы она не попала в коммит.
2. Сделать ветку поставщика от **прошлой** ветки поставщика (`vendor-77.248`):
   ```sh
   git worktree add -b vendor-<версия> ../wt vendor-77.248
   cd ../wt
   git ls-files server | grep -v '^server/acl.jsonc$' | git rm -q --cached --pathspec-from-file=-
   find server -mindepth 1 -maxdepth 1 ! -name acl.jsonc -exec rm -rf {} +
   cp -r /k/RPPCyber/<версия>/. server/
   git add -A server && git commit -m "Open77 <версия> vendor drop"
   ```
   В `server/` git хранит только файлы дистрибутива. `server.jsonc`, `server.host.jsonc`
   и `.open77/` в `.gitignore` и не затрагиваются, `acl.jsonc` наш и сохраняется.
3. В рабочей ветке: `git merge --no-commit --no-ff vendor-<версия>`.
4. Разрешить конфликты. Обычно это места, где мы перевели текст, а они поменяли код рядом.
   Брать их код и переносить наш перевод.
5. Перевести и перекрасить новые окна:
   - `tools/translate_ui.py extract` / `apply` — разметка `.rml`/`.html`;
   - `tools/translate_code.py` — строки в `.lua`/`.js`;
   - словари лежат в `tools/i18n/` (`ru_248.json` — строки 77.248);
   - `tools/recolor_ui.py --apply` — стили. В новых `.rml` заменить
     `nui://open77/open77.rcss` на копию `ui/open77-yellow.rcss` (см. [ui-theme.md](ui-theme.md)).
6. Сравнить список ресурсов в `server/templates/freeroam/template.json` старой и новой
   версии и так же поправить `resources.load` в `server.jsonc` и `server.host.jsonc`.
7. Проверить конфиг: `Open77.Server.exe --no-setup --config server.jsonc --check-config`
   (с `OP77_DATABASE_CONNECTION` в окружении). Запустить сервер и посмотреть,
   что все ресурсы дошли до `started`.
